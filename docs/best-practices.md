# 最佳实践

## 架构原则

- **机制 ≠ 策略**：把通用能力放进内核 / 服务，把业务策略留给软件层。
- **一类能力一个通用接口**：避免碎片化的同类入口。
- **合理默认 + 可覆盖**：给出安全默认，允许按需放开。

## 安全

- 监听地址默认 `127.0.0.1`；公网 / 局域网暴露前务必设置 `onebot.access_token` 与 Web 强密码（默认 `admin / admin123`）。
- 优先反向代理 + TLS 终止，框架不直接裸奔公网。
- 调试用扩展（`http_api` / `http_inject`）生产环境保持关闭。
- 外部通道如需裸 TCP，使用 `service/transport` 的认证帧，而非明文。

## 依赖与启动

- 生产环境启动前显式装好 `requirements.txt`，避免启动期联网自愈（开发便利，生产需可控）。
- `plugin.auto_install_deps_on_startup` 默认开，便于移机自愈；生产可关闭以确定性启动。

## 内存与稳定性

- 单插件上限 `plugin.max_memory_mb`（默认 64MB），连续超限会被看门狗自动卸载。
- 进程级上限 `service.watchdog.max_memory_mb`（默认 256MB）。
- 不要在 `register()` 内执行阻塞过久的同步操作；耗时任务交给 `ctx.task` 或异步协程。

## 文档与代码一致性

- 文档中所有路径、配置键、API 名称**以源码为准**；修改文档前先核验源码。
- 避免凭印象写文档——API 名 / 签名 / 路径 / 配置键须查源码核验。

## 事件与扩展

- `ctx.emit` 为延迟投递（handler 在 `register()` 返回后才触发），不要依赖同步立即生效。
- 多线程内 `emit` 会安全调度回主事件循环，不要自行 `asyncio.run` 新建循环。
- 同文件并发编辑会互相覆盖（后写覆盖前写），编辑同一文件请串行。
